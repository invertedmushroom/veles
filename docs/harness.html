Veles — The In-Browser Agent Harness

Calling a model is the easy part. Keeping a multi-turn, multi-tool agent coherent inside a browser tab — across file edits, user interruptions, approvals, and delegated subagents — is the job of the in-browser harness in src/kernel/.

Four-layer context assembly

Before every inference round, ContextBuilder.buildMessages reconstructs the conversation from the append-only journal and the live OPFS file tree rather than mutating an in-memory message array:

  • Hot-run window with substantive retention. selectHotRunIds keeps the latest run plus recent tool-bearing runs within hotRunWindow (default 2), so a brief conversational turn does not evict the prior tool turn that wrote the workspace files. Older runs fold large file-write payloads (<folded N chars; read from OPFS if needed>) and tool outputs over 200 characters.
  • OPFS sha256 drift notes. Every ToolResultCommitted records the sha256 hashes of files it read or wrote (observedFileHashes). If a user upload or another chat session later modifies or deletes one of those files, buildDriftAnnotation appends a [DRIFT NOTE] telling the model to call workspace.read_file before editing.
  • Interrupted tool-call repair. If a prior run was stopped or interrupted after ToolIntentLogged before ToolResultCommitted could be written (for example, when switching workspaces mid-tool), ContextBuilder synthesizes a closing TOOL_CALL_INTERRUPTED tool message so subsequent OpenAI turns never fail strict tool_call_id pairing.

Multi-tool batches, loop guards, and error recovery

Inside AgentKernelRuntime.executeInferenceCycle, each user turn can run up to 10 inference-and-tool rounds (maxToolRounds = 10):

  1. Sequential batch execution with approval pause/resume. When the model emits multiple tool calls in a single turn, executeToolCallBatch runs them in order. If a call in the middle of the batch requires user approval (such as workspace.delete_file), the kernel journals the remaining calls in ApprovalRequested.payload.remainingToolCalls, pauses in awaiting_approval, and resumes the rest of the batch once resolveApproval completes.
  2. Duplicate-call loop guard. Repeating the exact same toolName:argumentsJson signature within a run is intercepted by recordRepeatedCallLoopGuard, which commits a synthetic LOOP_GUARD_TRIGGERED tool result instructing the model to inspect existing workspace state instead of looping.
  3. Recoverable errors vs. uncertain side effects. executeToolWithSafeFallback catches non-abort errors thrown by pure_read and idempotent_write tools and returns them as ToolResultCommitted (ToolError: …) so the model can self-correct on the next round. Only non_idempotent tools halt the run in interrupted: uncertain_tool_outcome (KERN-INV-02).

Sessions and subagent delegation

AgentManager (src/kernel/agent-session.ts) multiplexes independent chat sessions over a single workspace's files. Calling agent.delegate (or its agent.spawn alias) spawns an isolated child session (sub-<role>-…) whose messages stay out of the parent's context window—only the child's final JSON summary returns to the parent tool call.

BoundaryEnforcement
Reserved session IDsChild calls cannot target session-main, their own parent, or another session's child (ERR_DELEGATE_RESERVED_SESSION_ID).
Tool capability ceilingChild sessions always set unrestrictedTools: false and intersect requested allowedTools with the caller's delegatableTools ?? allowedTools ceiling (defaulting to read-only inspection tools when omitted).
Origin-scoped credentialsA child session that overrides baseUrl only inherits the parent provider's apiKey when both URLs share the exact HTTP origin.
Cascading cancellationStopping a parent run aborts any active delegated child run and bubbles non-idempotent child tool uncertainty to the parent.

Browser-native tool suite

BrowserToolRegistry (src/kernel/tools.ts) exposes workspace, compute, web, image, and delegation tools directly in the Worker, and merges any remote schemas discovered from an optional Execution Gateway:

  • Workspace files: workspace.read_file, workspace.list_files, workspace.write_file, workspace.edit_file (exact target replacement), and workspace.delete_file (gated by interactive approval).
  • Isolated JS compute: workspace.run_script executes calculations against workspace text/CSV/JSON files in a capability-scrubbed worker, commits staged writeFile(path, data) updates, and returns a preview of written files alongside console/return output.
  • Public web & vision: web.fetch_url (normalizes GitHub /blob/ links to raw content and saves binary Uint8Array or text to OPFS via the SSRF-checked fetch proxy), web.search, workspace.inspect_image, image.generate, and image.transform.
