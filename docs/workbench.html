Veles — The 3-Pane Workbench

The workbench is the runtime's face: chat on the left, a code-and-preview inspector on the right, and a telemetry strip that shows which part of the harness is doing what, live, for every turn. Everything on this page is clickable down to the journal record that produced it.

Layout

The telemetry strip — the harness, made visible

Every turn renders its harness decision as pills across the top of the chat:

  • ⚡ router pill — the active decision engine and its tier: a Tier-1 hit names it, anything deterministic shows 🛡️ Tier-0 Gate, and an explicit fallback reason (timeout, not_configured, below_threshold…) is tagged on the pill itself. The tooltip carries the configured mode. Clicking inspects the exact journaled routing record — the same harnessRouting payload described in the routing walkthrough.
  • 🎯 specialist pills — one per injected capsule; a run with no matches shows a muted 🎯 base-workspace instead of pretending nothing happened.
  • 🧠 model pill — which model handled the turn.
  • 🪙 usage pill — cumulative tokens across multi-tool inference rounds, with prompt/completion split in the tooltip.
  • ⏱️ duration pill — turn wall-clock time.

The live pipeline bar

While a run is in flight, a four-stage indicator shows where it is — ⚡ 1. Route → 🧠 2. Reason → 🔧 3. Tool / Sandbox → 💾 4. Commit — lighting the active stage from the run's live state (inferring, awaiting approval, executing a tool) and dimming completed ones. It is the journal's state machine, animated.

Subagent cards and tool activity

Delegated child sessions (agent.delegate) appear as expandable 🤖 cards: the child's session id, model, scoped tool list, run state, token usage, and its own tool calls. Tool activity in the main timeline carries compact target chips — the file or query a tool acted on — so a twelve-tool turn reads like a story, not a log.

Workspace browsers

An overlay panel opens Files (searchable committed workspace, upload into it), Journal (searchable record stream — the same append-only journal the kernel commits), and Project (import/export archives). The chat is never the only way in: durable state is directly inspectable.

Installable, offline, phone-sized

The app ships as a PWA: the header exposes install, offline/online status, display mode, screen wake lock, document fullscreen, and update controls. ChatTimeline is styled through --veles-chat-* CSS custom properties, so the component can be reused and themed inside other PWAs without carrying the workbench's stylesheet along.

What the tests pin down

npm run test:browser   # real Chromium

tests/browser/workbench-ui.spec.ts asserts: submitted text appears immediately and Stop permits the next run; Stop at an approval keeps already-committed files and prevents the approved effect; mobile and fullscreen transitions preserve the mounted preview; and the PWA controls (manifest, install, wake lock, fullscreen, update) are all exposed. tests/browser/workbench.spec.ts exercises the real Web Locks, IndexedDB, OPFS, sandboxed preview, and live SSE inference paths.
