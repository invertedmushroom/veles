Veles — How a Turn Gets Routed

Before every inference round, the harness decides which specialist guidance should ride along. The decision is deterministic where possible, time-boxed where not, and always journaled before inference starts.

Routing runs every round

buildRoundMessages executes before every inference round of the agent loop, so routing is recomputed per round. It re-reads the run's original RunCreated prompt each time and matches it against the registered specialist profiles. The outcome is journaled as a CheckpointCommitted record carrying payload.harnessRouting — {source, specialistIds, configuredMode, fallbackReason?} — committed before the model is called. Because Tier 0 is deterministic, a replayed run reconstructs the same routing decision from the same prompt.

Tier 1 — the Decision API

When a classifier is configured, each registered specialist gets exactly one predicate question — "Does this task need X expertise?" followed by its routing hint and keywords — posted to a Decision API backed by TypeSafe (jev-1.14.0), an OpenAI-compatible Decisions endpoint (gpt-6-luna), or a local model (laya-latest) depending on mode. Responses scoring ≥ the configured threshold (default 0.75) are sorted by probability and the top two specialist IDs win.

The call is hard-bounded at 800 ms (a raced abort deadline, tunable). On timeout or HTTP error the endpoint is quarantined for the rest of the session — it is not asked again — and routing falls to Tier 0 with an explicit reason.

What the Decision API never sees

The privacy boundary is structural, not a policy: the request carries only the prompt with secret-looking tokens replaced by <REDACTED> and truncated to the last 3000 characters, plus the first 20 workspace file paths. Specialist capsule text never leaves the browser, and the response is only specialist IDs and probabilities. The model that routes is not the model that reasons, and the router cannot read your workspace.

Tier 0 — deterministic matching

Anything short of a confident Tier-1 hit — and every run with no classifier configured — matches profiles locally: keyword regex with word boundaries against the lowercased prompt, or a path-pattern hit where the prompt mentions a workspace file. Matches are priority-sorted, capped at two. Same prompt, same paths, same capsules — which is what makes the journaled routing record trustworthy under replay.

Undecided has a name

Every non-hit carries an explicit fallbackReason on the journaled record instead of silently degrading:

ReasonMeaning
tier0_onlyTier 1 disabled by configuration; deterministic routing is the intended mode.
not_configuredNo classifier is registered for the configured mode.
missing_api_keyThe configured mode needs a key and none is present.
timeoutThe Decision API missed its 800 ms deadline.
http_<status>The Decision API answered with an HTTP error (e.g. http_429); endpoint then quarantined.
endpoint_unavailableThe endpoint was already quarantined earlier in the session.
network_errorThe request failed at the transport level.
below_thresholdScores came back but none reached the threshold.
classifier_errorThe classifier call threw.
unknown_specialistThe classifier named a specialist absent from the registry.

Total miss on both tiers is also explicit: an empty capsule list, and the guidance section simply is not included.

Injection

Matched capsules land in the system header, assembled in a fixed order: identity line, workspace folder conventions, the preview-sandbox contract, the committed OPFS file tree (each path with an 8-hex sha256 prefix), and — only when at least one capsule matched — an --- Active In-Browser Specialist Guidance --- section with each capsule's prompt verbatim. The whole header ships as a single system message; the conversation messages themselves are never modified by routing.

The durable record — and the pill

The routing decision the loop actually used is the one in the journal: payload.harnessRouting with source of tier1_classifier or tier0_deterministic. The workbench's ⚡ router pill (data-testid="harness-router-pill") renders the latest round's record — a Tier-1 hit shows the active decision engine, anything else shows 🛡️ Tier-0 Gate with the fallback reason — and clicking it inspects the raw record in the run inspector.
